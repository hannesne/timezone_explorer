# Timezone Explorer

## Description
A minimal React Vite TypeScript app that shows five clocks:
UTC, Pacific/Auckland, America/New_York, Asia/Kolkata, and Asia/Kathmandu.
Each clock shows the local date as YYYY-MM-DD and the time as 24-hour HH:mm:ss for a single shared instant.
The clocks update every second and also refresh on window focus or document visibility.

The app respects IANA timezones, including daylight saving transitions and fractional offsets,
and displays explicit errors if timezone names are invalid.

## Development Setup

### Prerequisites
- Node.js 24.21.0 (exact version required)
- npm (comes with Node.js)

### Installation
Run the following command to install dependencies:
```bash
npm ci
```

### Start Development Server
Starts the Vite dev server which reloads on source changes:
```bash
npm run dev
```
Open your browser to `http://localhost:5173` (or as indicated) to see the app.

### Type Checking
Run the TypeScript compiler in strict mode without emission:
```bash
npm run typecheck
```

### Unit Tests
Run Vitest unit tests for the time formatting utility:
```bash
npm run test:unit
```

### Build Production
Build optimized production files into `dist`:
```bash
npm run build
```

### End-to-End Browser Tests
Run Playwright tests for UI and integration verification:
```bash
npm run test:e2e
```

## Usage
The app renders five fixed timezone clocks with labels and current date/time.
No additional user settings or interactions.

## Accessibility
- Each clock row is labeled with the timezone name.
- Invalid timezone errors are shown with `role="alert"` for screen readers.

## File Overview
- `index.html`: HTML entry with root div and script include.
- `src/time.ts`: timezone formatting utility with IANA validation.
- `src/main.tsx`: React app with state and effects for time updates.
- `src/time.test.mts`: Vitest unit tests.
- `src/playwright.config.mts`: Playwright test configuration.
- `src/browser/clock.spec.mts`: Playwright UI tests.
- `package.json`: project scripts and metadata.

## Notes
Do not modify `package.json` fields beyond `scripts`.
No persistence, pickers, external API, login, or settings.
All clocks share a single sampled instant.
